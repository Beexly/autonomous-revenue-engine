DIY: the free 15-point checklist

This is the real checklist, not a teaser. If you work through it yourself and get stuck, that's what the diagnostic is for.

  1. Inventory events. Events Manager → Data sources → your Pixel. List every event arriving via Browser, Server, or Both. Anything business-critical (Purchase, Lead, InitiateCheckout) should be Both.
  2. Check dedup status. For each "Both" event, open it and look for "deduplicated" statistics. Meta dedupes when browser and server send the same event_name + event_id. No shared event_id → you are double-counting.
  3. Verify event_id generation. The SAME unique id must be produced once per user action and passed to BOTH the Pixel call and the CAPI payload. Two independent random ids = no dedup. (Shopify native + a custom CAPI app is the classic double-count setup.)
  4. Confirm the dedup window. Server event must arrive within 48h of the browser event; in practice send within minutes. Batched nightly CAPI uploads of events the Pixel already sent will double-count.
  5. Score EMQ per event. Events Manager shows Event Match Quality (1–10) for server events. Under 6 is leaving performance on the table; 8+ is the goal for Purchase/Lead.
  6. Fix EMQ inputs. EMQ rises with matched customer parameters: email (em) and phone (ph) as SHA-256 of lowercase/trimmed values, external_id, fbp/fbc cookies forwarded from the browser, client IP + user agent on website events. Check which are absent per event — that's your fix list.
  7. Normalize before hashing. Lowercase, trim, strip formatting BEFORE SHA-256 (phone in E.164 digits). Hashing " Name@Gmail.com" and "name@gmail.com" produce different hashes — silent match-rate killers.
  8. Check action_source. Server events must carry the true source (website, physical_store, etc.). Wrong action_source risks rejection and skews attribution.
  9. Forward fbp/fbc. Your server events should include the _fbp cookie and, when a click id exists, fbc. Missing fbc on paid-click conversions is one of the most common attribution leaks.
  10. Use Test Events before trusting anything. Events Manager → Test events + test_event_code on server payloads. Trigger a real test purchase; watch browser + server rows arrive and dedupe live.
  11. Reconcile against your backend. Pick 7 days. Compare Meta-reported Purchases vs your store's actual orders. Within ~5–15% is normal (attribution modeling); 30%+ high = double-counting; large undercount = events not firing or being rejected.
  12. Check event coverage after consent banners. Test as an EU/consent-declined visitor: does your CAPI still send server events you're allowed to send? Consent tools silently killing the Pixel while CAPI keeps firing (or vice versa) breaks dedup assumptions.
  13. Look for rejected/filtered events. Events Manager → Diagnostics tab. Address every active issue; rejected events never make it into optimization.
  14. Verify domain + aggregated setup. Domain verified in Business Manager; web events configured. Unverified domains degrade delivery of your conversions.
  15. Re-check after every theme/app/checkout change. Tracking breaks silently on redesigns and app installs. Calendar a monthly 10-minute pass of items 2, 5, 11, 13.
